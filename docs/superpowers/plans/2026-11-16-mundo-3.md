> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seis níveis novos no terceiro andar — classes e objetos; construtores e encapsulamento; herança; polimorfismo; classes abstratas e interfaces; static, enum e struct — cada um com vinheta, página no Grimório e testes; e o motor preparado para o jogador escrever as suas próprias classes.

**Architecture:** No Mundo 3 o marcador `// {{PLAYER_CODE}}` fica **ao nível do ficheiro**: o jogador escreve classes completas (e `using` permitidos), como num `.cs` real. A `Validation` volta a ser uma classe de topo à parte (como no Mundo 1) que cria os objetos do jogador. O motor tem de guardar todos os corpos que o jogador pode escrever (métodos, construtores, acessores, inicializadores), rejeitar o que ainda não é ensinado ou é perigoso, e explicar os erros novos de POO. Os níveis continuam a ser só conteúdo.

**Tech Stack:** .NET 10 (`net10.0`, SDK 11), Roslyn, Blazor, xUnit, bUnit, Playwright.

**Spec:** `CLAUDE.md` (roteiro: "Mundo 3 – POO: classes e objetos; construtores e encapsulamento; herança; polimorfismo; classes abstratas e interfaces; static, enum e struct"; "`class`, `using` e `namespace` só aparecem no Mundo 3").

## Decisões confirmadas pelo João (2026-11-16)

1. **O que o jogador escreve:** um **ficheiro com classes** (`class Hero { ... }` ao nível do ficheiro). `using` é permitido, só para os namespaces da lista permitida; `namespace` continua fora (rejeitado), para simplificar. A `Validation` é uma classe à parte que cria os objetos do jogador.
2. **Quantos níveis:** **6**, um conceito por nível (12 a 17).

## Decisões (Opus)

- **Template do Mundo 3:** `Template.cs` contém só a linha `// {{PLAYER_CODE}}`. `Validation.cs` é `public static class Validation` de topo (forma do Mundo 1), com tipos da biblioteca totalmente qualificados (`global::System.…`), porque o jogador pode declarar classes com nomes como `Math` ou `List`.
- **Nomes reservados:** o jogador não pode declarar tipos chamados `Validation` nem nomes começados por `__` (mensagem "O nome X está reservado; escolhe outro nome.", que já existe para `Validation`).
- **O que fica rejeitado no Mundo 3** (por não ser ensinado ou por poder derrubar o processo): `namespace`, destrutores/finalizadores (correm na thread do GC; uma exceção mata o processo), operadores e conversões, eventos, `record`, `delegate`, `async`, `extern`. Tipos aninhados, propriedades, construtores (incluindo `static`) e genéricos são permitidos — todos com corpo guardado.
- **Validação por reflexão:** a `Validation` é código de confiança e pode usar `typeof(...)` e reflexão para verificar a forma (ex.: "o set de Armor é private", "Cat.Speak é override", "Rune é struct"). O resultado continua a ser `(Case, Expected, Actual)` com literais C# ou descritores curtos em inglês (`private set`, `override`, `struct`), como o `CLAUDE.md` já permite.
- **Regra de desenho (lição do Mundo 2):** nenhum nível se passa saltando o conceito. Cada nível tem pelo menos uma verificação que só passa com o conceito (objetos independentes, `private set`, herança real, `override`, `abstract`/interface, cópia por valor da `struct`).
- **Tema do andar:** "O Bestiário Encantado" / "The Enchanted Bestiary" — o mago descreve criaturas como classes (molde) e cria-as como objetos. `map.floor.3` "Mundo 3 · Terceiro andar" / "World 3 · Third floor"; teaser "Mundo 4 · Genéricos, lambdas e LINQ — em breve" / "World 4 · Generics, lambdas and LINQ — coming soon".
- **Estrelas:** como no Mundo 2 (dica tira a 2.ª estrela). Os limites de instruções contam instruções dentro de todos os corpos (métodos, construtores, acessores); cada nível confirma que a solução simples ganha 3 estrelas.

## Review Focus

1. Recursão sem nenhum método escrito: `class A { A next = new A(); }` (inicializador que constrói o próprio tipo pelo construtor implícito) e `static int X = Y; static int Y = X + F();` têm de dar a explicação de recursão ou um erro, nunca derrubar o servidor. Task 1.
2. Recursão e ciclos dentro de construtores, `get`/`set`, `ToString()`/`Equals()`/`GetHashCode()` sobrepostos (chamados pela própria biblioteca, ex.: interpolação ou `Dictionary`) → `RuntimeError`/`TimedOut`, nunca crash. Task 1.
3. Um finalizador (`~Hero()`) que lança, ou um construtor `static` que lança, não pode derrubar o processo: finalizador rejeitado; `TypeInitializationException` vira `RuntimeError` explicado. Task 1.
4. Erros novos mais prováveis do iniciante — classe com nome errado, construtor com argumentos errados, membro `private` usado de fora, `override` sem `virtual`, interface/abstrato por implementar, `new` numa classe abstrata — com explicação PT/EN na linha certa. Task 2.
5. Esquecer `override` (esconder o método) não dá erro de compilação, só um aviso: o nível de polimorfismo tem de mostrar ao jogador porque falhou (verificação "override"). Task 7.

#### Task 4: Nível 12 `12-classes` — classes e objetos (página `classes`)
- Pedido: `class Slime` com campos públicos `string Name` e `int Health`, método `void Hit(int damage)` (tira vida, nunca abaixo de 0) e `bool IsAlive()`.
- Verificações: `Health` depois de `Hit(3)` numa slime com 10 → 7; `Hit(20)` → 0; `IsAlive()` com 0 → `false`; **duas slimes são independentes** (`a.Hit(5)` não muda `b`) — apanha campos `static`.
- Vinheta: uma slime num frasco de vidro do bestiário. Ícone `slime`.
- Testes extra: `Level12_StaticHealth_IsRejected` (objetos partilham vida → falha), `Level12_MissingClass_Explains` (usa a explicação CS0246 da Task 2).

#### Task 5: Nível 13 `13-constructors` — construtores e encapsulamento (página `constructors`)
- Pedido: `class Golem` com construtor `Golem(string name, int armor)` (armadura negativa vira 0), propriedade `string Name { get; }`, `int Armor { get; private set; }` e `void Crack()` (tira 1, nunca abaixo de 0).
- Verificações: `new Golem("Rocky", 3).Armor` → 3; 4× `Crack()` → 0; `new Golem("Pebble", -2).Armor` → 0; **forma**: setter de `Armor` → `private set`; `Name` sem setter público → `no public set`.
- Vinheta: golem de pedra com uma placa de armadura. Ícone `golem`.
- Testes extra: `Level13_PublicSetter_IsRejected`, `Level13_PrivateMemberUsedOutside_Explains` (CS0122/CS0272).

#### Task 6: Nível 14 `14-inheritance` — herança (página `inheritance`)
- Pedido: `class Creature` com construtor `(string name, int health)`, campos/propriedades `Name`, `Health` e `string Describe()` → `"Smaug (50)"`; `class Dragon : Creature` com construtor `(string name, int health, int fire) : base(name, health)` e `int Breathe()` → `fire * 2`.
- Verificações: `new Dragon("Smaug", 50, 7).Describe()` → `"Smaug (50)"`; `Breathe()` → 14; **herança real**: `new Dragon(...) is Creature` → `true`; `Describe` declarado só em `Creature` (reflexão: `DeclaringType` → `Creature`).
- Vinheta: um dragão pequeno ao lado de um molde de criatura. Ícone `dragon`.
- Testes extra: `Level14_CopiedInsteadOfInherited_IsRejected`, `Level14_MissingBaseCall_Explains` (CS7036 no construtor base).

#### Task 7: Nível 15 `15-polymorphism` — polimorfismo (página `polymorphism`)
- Pedido: `class Creature` com `virtual string Speak()` → `"..."`; `class Cat : Creature` → `"Meow"`; `class Owl : Creature` → `"Hoot"`.
- Verificações: num `Creature[] { new Creature(), new Cat(), new Owl() }`, as falas → `{ "...", "Meow", "Hoot" }` (chamadas pela referência base); **forma**: `Cat.Speak` e `Owl.Speak` → `override` (reflexão; esconder com `new` ou sem palavra dá `hides (missing override)`).
- Vinheta: gato e coruja em frente a um coro de criaturas. Ícone `masks`.
- Testes extra: `Level15_HidingInsteadOfOverride_ShowsWhy`, `Level15_OverrideWithoutVirtual_Explains` (CS0506).

#### Task 8: Nível 16 `16-interfaces` — classes abstratas e interfaces (página `abstract-interfaces`)
- Pedido: `interface IFlyer { int FlySpeed(); }`; `abstract class Beast` com `abstract string Sound()` e `string Roar()` → `Sound().ToUpper() + "!"`; `class Griffin : Beast, IFlyer` (`"screech"`, 30).
- Verificações: `new Griffin().Roar()` → `"SCREECH!"`; `((IFlyer)new Griffin()).FlySpeed()` → 30; **forma**: `Beast` → `abstract class`; `IFlyer` → `interface`; `Roar` declarado em `Beast`.
- Vinheta: grifo a voar sobre um pedestal vazio (o molde abstrato). Ícone `griffin`.
- Testes extra: `Level16_ConcreteBeast_IsRejected`, `Level16_MissingImplementation_Explains` (CS0534/CS0535), `Level16_NewAbstract_Explains` (CS0144).

#### Task 9: Nível 17 `17-static-enum-struct` — static, enum e struct (página `static-enum-struct`)
- Pedido: `enum Element { Fire, Water, Earth }`; `struct Rune` com `Element Element` e `int Power`; `static class RuneMath` com `static int Total(Rune[] runes)` e `static Element Strongest(Rune[] runes)` (a de maior poder; primeira em caso de empate).
- Verificações: `Total` de três runas → soma; `Strongest` → `Element.Water`; **cópia por valor**: `var a = new Rune { Power = 1 }; var b = a; b.Power = 9;` → `a.Power` = 1 (com `class` dá 9); **forma**: `Rune` → `struct`, `RuneMath` → `static class`, `Element` → `enum`.
- Vinheta: três runas (fogo, água, terra) gravadas numa pedra. Ícone `runes`.
- Testes extra: `Level17_RuneAsClass_IsRejected`, `Level17_RuneMathNotStatic_IsRejected`.
